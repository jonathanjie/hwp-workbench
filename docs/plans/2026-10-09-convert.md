# Explicit document conversion implementation plan

**Goal:** Implement Brief E: reported, opt-in exports through HWPX without changing native save behavior.

**Architecture:** A bounded standard-library reader maps DOCX and HWPX to a small rich document model. Dedicated writers emit packages. A conversion operation chains these mappers with the existing rhwp bridge and an optional isolated LibreOffice process, then re-reads text before exclusive publication.

**Tech stack:** Python standard library, existing rhwp bridge, optional local LibreOffice.

1. Write self-authored DOCX tests for headings, runs, paragraph geometry, lists, merged tables, images and page setup. Confirm failure, then implement DOCX reading and HWPX writing. Check native reopen, rhwp probe and page-zero rendering. Update `work/results/E.json`.
2. Add HWPX rich reading and DOCX writing with reverse mapping tests. Check paragraph text and optional LibreOffice PDF validation. Update the result.
3. Add the shared conversion operation and small additive CLI/MCP registrations. Test dry runs, all available routes and reports. Update the result.
4. Add malformed-package, unsupported-feature, injected-loss, no-overwrite, confinement and LibreOffice timeout regressions. Keep optional tool skips explicit. Update the result.
5. Document conversion limits and report fields. Run `python3 scripts/run-tests.py` and `npm run check`, plus a clean-copy run without local-only folders. Record host, skips and remaining qualification gaps. No git writes.
